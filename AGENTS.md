# Repository guidance

- Follow `CONTRIBUTING.md` for branch, commit, review, and verification rules.
- Use OpenSpec for behavior, architecture, API, data, security, and cross-module contract changes. Keep accepted behavior in `openspec/specs/` and active deltas in `openspec/changes/`.
- Read relevant architecture documents and ADRs before changing their contracts. Keep OpenSpec and architecture evidence aligned; do not rewrite unrelated existing documents.
- Preserve the existing structure and avoid dependencies or generated files without a project need.
- Run relevant checks and report commands and outcomes accurately.
