# ARC-00의 기술 결정 검토

검토 기준: 사용자가 제공한 [ARC-00 v0.1](ARC-00.md), 2026-11-16. 아래는 ARC-00의 결정 요약을 추적하기 위한 검토표다. 당시 결정의 전문 ADR을 새로 작성하거나 검증된 결론으로 격상하지 않는다. 상태는 설계 수준의 방향과 기술 검증 상태를 분리해 표시한다.

| ID | ARC-00의 1차 방향 | 현재 설계 처리와 남은 검증 | 관련 문서 |
|---|---|---|---|
| ADR-001 | Local-first 데스크톱 앱 | 로컬 저장을 기본으로 하고 외부 Provider 전송을 별도 표시한다. 전송 범위와 개인정보 처리는 실제 흐름에서 검증 | ARC-01/02/06/08/09/10 |
| ADR-002 | Flutter Desktop GUI | 1차 방향 유지. 대상 OS, 접근성 및 실제 지원 범위는 검증 전 | ARC-01 |
| ADR-003 | 로컬 코어·모듈형 모놀리스 | 논리 계층을 프로세스 경계로 단정하지 않는다. 언어·IPC·배포와 장애 격리는 미정 | ARC-01/06/10 |
| ADR-004 | Provider 중립 Agent Schema와 Adapter | 정의·실행·변환 계약을 분리한다. 형식 변환과 기능 손실은 Provider별 확인 | ARC-03/04/05/06 |
| ADR-005 | 공식 인증 우선·API 키 입력 최소화 | 공식 경로를 우선하고 비공식 토큰 추출을 금지한다. 외부 GUI 연동 허용과 계정 격리는 Provider별 검증 | ARC-05/06 |
| ADR-006 | SQLite를 작업 상태 저장소 후보로 사용 | 후보로 유지하며 확정하지 않는다. 트랜잭션·내구성·마이그레이션과 장애 복구 검증 필요 | ARC-10 |
| ADR-007 | 로컬 산출물·Git 및 필요 시 Worktree | 파일 충돌 완화와 버전 관리 방향. Worktree는 샌드박스가 아니며 경로·병렬 충돌 검증 필요 | ARC-04/07/09/10 |
| ADR-008 | 상태·원본 기록·검증된 결정·장기 기억 분리 | 각 정본과 파생 인덱스를 구분한다. 원본의 민감정보·보존·삭제 정책은 미정 | ARC-07/08/10 |
| ADR-009 | 위험 작업의 권한 제한·사용자 승인 | 승인 범위와 집행 경계를 분리한다. OS·Provider별 실제 집행 및 실행 중 철회는 확인 필요 | ARC-04/06/09 |
| ADR-010 | 단일 에이전트 기준선과 구성 비교 | 동일 조건의 비교를 제안한다. 데이터셋·측정 방식·합격치와 비용 가용성은 미정 | ARC-03/09 |
| ADR-011 | 세션 상태·체크포인트 기반 복구 | 복구 가능 여부를 Provider Capability로 확인하고 불명확하면 Unknown으로 보존한다. 실제 재개·관찰 가능성은 미검증 | ARC-05/06/07/10 |
| ADR-012 | 실행·인증 기능을 Capability로 표현 | supported / unsupported / unknown을 구분한다. 스키마·기능별 근거와 버전별 지원은 미정 | ARC-03/05/06 |

[ADR-013](adr/ADR-013-runtime-observation.md)은 ARC-06/07/10의 불확실한 외부 실행 결과 처리에 관한 신규 제안이다. 기존 ADR의 변경 또는 구현 검증 완료가 아니다.

## 후속 설계 상태 · 2026-11-16

위 내용은 작성 당시의 기록이다. 이후 [ARC-11](ARC-11.md)~[ARC-14](ARC-14.md) 설계 제안과 [요구사항·수용 기준](REQUIREMENTS_ACCEPTANCE.md), ARC-09/10 보완 계약을 추가했다. 사용자 승인과 실제 OS·Provider·저장소 시험은 미완료이며 GitHub Projects 상태를 자동 변경하지 않았다. 과거의 미착수·미정 표현은 이 후속 설계의 존재나 제안된 기본값을 부정하지 않는다.
