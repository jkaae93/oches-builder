# ADR-015: 템플릿과 프로젝트 인스턴스의 분리

상태: 제안 · 2026-11-16 · 관련: ARC-00, ARC-01/03/04/07/10/11, 제안 ARC-15. 구현과 지원 검증 전이다.

## Context
기존 ARC-03은 구조를 추천하고 ARC-04는 Agent Definition을 관리하지만, 재사용 가능한 기본/사용자 템플릿과 프로젝트 간 생명주기는 소유하지 않는다.

## Problem
기본 원본을 보존하고 여러 클라이언트와 프로젝트에서 사용자의 정의를 재사용하면서 실행 환경과 비밀정보에 종속되지 않아야 한다.

## Considered Alternatives
1. ARC-03에 저장·추천·검증을 통합: 모듈 수는 적지만 추천과 버전·가져오기 생명주기가 결합된다.
2. 각 클라이언트가 독립 템플릿을 보유: 단순한 오프라인 UX가 가능하지만 정본 충돌과 보안 정책 중복이 생긴다.
3. 공유 Core의 독립 Registry/Validator와 프로젝트별 인스턴스: 공통 계약과 재사용에 유리하나 버전·충돌·권한 설계가 필요하다.

## Decision
3안을 권장한다. ARC-15를 템플릿 정의·Registry·Validator의 후속 설계 ID로 예약하고 기존 ARC-03의 추천, ARC-04의 에이전트 정의, ARC-07의 실행 책임을 유지한다. 템플릿 버전과 인스턴스는 독립하고 기본 원본은 수정하지 않는다. JSON/YAML은 버전이 명시된 교환 형식 후보이며 물리 스키마는 확정하지 않는다.

## Rationale
생명주기와 추천·실행 책임을 분리해 기본/사용자 템플릿을 여러 클라이언트에서 일관되게 재사용하고 출처와 사용자 데이터 보존을 명확히 한다.

## Trade-offs
공통 저장·버전·마이그레이션과 클라이언트 충돌 처리가 필요하다. 선택 시 복사 방식은 원본 변경의 자동 반영이 없으므로 사용자가 새 버전을 명시적으로 적용해야 한다.

## Consequences
ARC-15와 ARC-11·ARC-10 계약이 필요하다. 외부 가져오기는 비신뢰 데이터이며 비밀정보와 실행 권한을 전달하지 않는다. 작업 의존성은 DAG를 기본으로 하고 제한된 반복 표현은 별도 검증한다. 기존 문서에 영향 경계를 추가한다.

## Verification Requirements
기본 원본 불변, 버전별 이력과 인스턴스 독립성, 충돌·삭제·마이그레이션 후 데이터 보존, JSON/YAML 악성 입력, Capability 미확인과 사용자 승인 경계, 플랫폼별 접근 제한을 검증한다.

## Unresolved
정확한 스키마·직렬화 및 YAML 보안 제한, 버전 호환·복구, 서브그래프와 제한된 반복, 기본 제공 목록, 클라이언트별 편집 범위, 사용자 템플릿 삭제 정책의 상세 UX.
