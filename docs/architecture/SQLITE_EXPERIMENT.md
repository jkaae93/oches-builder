# SQLite 후보 기초 검증 기록

일시: 2026-11-16 · 환경: 이 컴퓨터의 Python sqlite3, SQLite 3.51.0 · 대상: 임시 디렉터리의 독립 데이터베이스. 프로젝트 파일·사용자 데이터는 사용하지 않았다.

| 시나리오 | 수행 | 관찰 |
|---|---|---|
| 상태·이벤트 롤백 | 동일 트랜잭션에서 상태 업데이트와 이벤트 삽입 후 예외를 주고 rollback | 이전 버전이 유지되고 이벤트가 남지 않음 |
| 중복 operation ID | UNIQUE 제약을 둔 테이블에 동일 ID 재삽입 | IntegrityError 발생 |
| 낡은 기대 버전 | 별도 연결에서 기대 버전 0을 조건으로 현재 버전 1의 행을 업데이트 | 변경 행 수 0, 기존 버전 1 유지 |

세 검사는 통과했다. 이것은 SQLite의 해당 단순 조건에 대한 관찰이지 Oches Build Studio의 Repository, 이벤트 정렬, 동일 ID의 내용 비교, 다중 프로세스 경합, 디스크 장애, 강제 종료, 내구성, 마이그레이션이나 보안이 구현·검증됐다는 뜻이 아니다. OS·SQLite 설정·버전별 실제 조건의 시험과 저장 기술 선택은 여전히 필요하다. 외부 CLI 실행은 데이터베이스 트랜잭션에 포함되지 않는다.
