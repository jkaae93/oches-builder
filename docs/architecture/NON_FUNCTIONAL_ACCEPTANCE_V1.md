# 접근성·성능·운영 요구 수용 기준 v1 — 제안

상태: 미승인 설계안 · 2026-11-16. 이 문서는 ARC-01/02/06/09/10/11/12/13/14의 비기능 요구와 검증 가능한 **후보 기준**이다. 제안 수치는 관측한 성능도 출시 약속도 아니다. 실제 OS·하드웨어·Provider·도구와 평가자, 사용자 승인 전 항목은 NOT RUN이다. 각 기준의 미충족·미관측을 통과로 계산하지 않는다.

## A. 접근성의 기준과 검증 범위

초기 목표: Desktop, VS Code Webview와 Chrome Side Panel에서 핵심 흐름(프로젝트 선택 → 범위/제약 → 추천/템플릿 → 검증 → 승인 → 실행 상태/취소 → 평가/오류)을 키보드와 해당 플랫폼의 스크린리더로 수행할 수 있어야 한다. 그래프의 노드·연결·순서를 조작하는 동등한 목록/명령 경로를 제공하며 드래그 하나만 요구하지 않는다. 일반 웹 콘텐츠는 [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/) AA 성공 기준을 검토 대상으로 하고 해당 기준의 적용 가능성을 개별 기술·플랫폼에 맞게 평가한다. WCAG는 웹 콘텐츠 기준이므로 이 목표만으로 Flutter 네이티브나 전체 제품의 인증·법적 적합성을 주장하지 않는다.

## B. 성능·자원·사용량 후보 기준

아래는 제품 설계 검토용 초기 제안값이며 측정값이 아니다. 최소 실험 머신의 후보 환경은 같은 macOS 버전의 로컬 파일시스템, 4 CPU 코어·8 GiB RAM 이상의 단일 사용자 환경이다. 시험 배치의 모든 회차에는 하나의 실제 기기를 사용하고 정확한 CPU 모델·논리 코어·RAM·저장장치·OS/버전, 절전·작업 부하와 파일 캐시 조건을 사전 고정·기록한다. 다른 기기 결과를 같은 배치로 합산하지 않는다. 특정 기기의 성능을 예측하는 값이 아니며 최종 OS·머신·대상 범위와 기준값은 실제 측정 전 승인돼야 한다. 확정되지 않은 항목은 NOT RUN/미승인이다.

## C. 지원·복구 및 데이터 보호의 수용 경계

- 데이터·실행 상태: [계약 사례](CONTRACT_ACCEPTANCE_MATRIX.md) X10~X21의 모든 필수 양성/부정 대조에서 잘못된 중복 실행·부분 커밋·다른 버전 평가 재사용 0건. 증거가 없는 사례는 NOT RUN. 상태 저장과 외부 프로세스는 원자적이지 않다.
- 오류 표시: 독립적으로 유도한 연결 단절, 저장 실패, 권한 거부, 승인 만료, unsupported/unknown 중 하나라도 성공으로 표시되면 FAIL. 저장된 구체 상태와 UI의 구분을 확인한다.
- 개인정보: 비밀 탐지가 완전하다고 주장하지 않는다. 승인 없는 전송·알려진 시험 비밀의 진단 복제·권한 밖 조회가 독립 관측되면 FAIL. 탐지/관측이 불완전하면 보안 PASS가 아니다.
- 호환성: [Capability 계약](CAPABILITY_CONTRACT_V1.md) CV01~18에서 해당 범위 하나만 바꾼 사례를 따로 판정한다. 문서의 기능 지원은 제품 지원으로 승격하지 않는다.

## D. 승인과 변경

제품 소유자·접근성 검토자·기술 검토자는 실제 시험 전에 대상 환경·시나리오·제안 수치·증거 저장/삭제를 검토한다. 승인되지 않은 기준도 설계 검토에서 문서의 완결성을 평가할 수는 있으나 제품의 수용·성능·접근성 합격 결과로 표현해서는 안 된다. 하드웨어 또는 입력 규모가 달라지면 새 시험 계획/버전으로 기록한다. [평가·관측 명세](EVALUATION_OBSERVABILITY_SPEC.md)의 판정·결측·분모 규칙은 별도로 적용한다.
