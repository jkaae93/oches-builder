# 상세 설계 정합성 검토

검토일: 2026-11-16. 대상: 대화로 제공된 ARC-00 v0.1 및 로컬 ARC-01~10 초안. 문서 검토이며 구현·공식 Provider 연동 시험이 아니다.

## 검토 결과
| 경계 | 검토 결과 | 잔여 검증 |
|---|---|---|
| ARC-02 → 03 | Profile의 버전·근거·불확실성을 추천 입력에 반영 | 구체 스키마와 파일 변경 감지 |
| ARC-03 → 04 → 09 | 제안 승인과 파일 적용 승인을 분리하고 계획 변경 시 재승인 | 실제 파일별 원자성 및 복구 |
| ARC-05 → 06 | 계정 참조 및 기능 상태를 실행 전 재확인, unknown 필수 기능 차단 | 공식 인증·격리·기능별 지원 |
| ARC-06 → 07 → 10 | 시도와 작업을 분리; 시작 기록과 외부 실행 사이 불확실성을 Unknown/Blocked로 보존 | OS·Provider별 프로세스 관찰과 재개 |
| ARC-07 → 09 | Runtime 종료와 평가 통과를 구분하고 상한 내 재작업 | 평가 데이터셋과 합격치 |
| ARC-08 → 10 | 기억의 출처와 유효 상태를 기록하고 요약을 작업 정본으로 쓰지 않음 | 접근·보존 정책과 인덱스 복구 |
| ARC-01 → 전체 | 미확인 기능·stale 결과·취소 요청과 실제 종료 구별 | 접근성 및 플랫폼별 UI 시험 |

ADR-013은 외부 프로세스와 상태 저장을 단일 트랜잭션으로 오인하지 않도록 제안한다. 정확히 한 번 실행은 보장하지 않는다. 사용자는 ARC-01~10 설계 초안의 검토 후 승인을 선택했다. 실제 Provider 및 저장소 검증은 별도로 남아 있다.

## 확인 방법과 한계
각 ARC 문서의 요구 항목 표기와 Markdown 코드 펜스 쌍을 기계적으로 검사했고, 위 경계와 상태 전이를 문서 수준에서 대조했다. Mermaid 21개 다이어그램은 2026-11-16 Chromium에서 Mermaid parse 및 SVG render를 통과했다. 이는 시각적 가독성, 구현 동작, 보안 강제, 부하·장애 실험 또는 실제 Provider 약관 준수를 증명하지 않는다. 모델·CLI·OS를 특정한 실행 시험은 수행하지 않았다. 기존 원격 저장소에는 ARC-00 파일이 없었다. 대화의 사용자 원문을 로컬 ARC-00.md로 복원해 문자열 대조했으며 원격에는 반영하지 않았다.

## 후속 검증 게이트
1. ARC-00 원문은 대화 기록과 문자열 대조하여 로컬에 보존했다. 원격 등록은 별도 작업이다.
2. 사용자가 ARC-01~10과 ADR-013을 검토한다. 미확정 사항을 결정하고 각 문서의 교차 계약을 갱신한다.
3. 최초 OS·CLI를 선정해 공식 정책과 버전별 Capability, 계정 격리·취소·재개·승인 집행을 실험한다.
4. 저장소 기술 선정 후 장애 주입으로 상태 기록과 프로세스 생성 사이 복구, 동시성, 민감정보 보호를 검증한다.
5. 평가 데이터셋·지표·합격치를 확정하고 단일 에이전트 기준선과 비교한다.

추가 검토에서 ARC-06의 시작 중단과 ARC-07의 Blocked 복구를 대조해, 앱 종료만으로 외부 프로세스 종료를 추정하지 않으며 기존 시도의 종료 확인 전 재실행하지 않도록 수정했다. ARC-07에 Runtime 상태별 작업 상태 대응표를 추가했다.

ARC-04의 다중 파일 적용 실패를 검토하여 부분 적용 및 결과 불명 상태를 추가했다. 모든 대상의 적용 결과가 확인된 경우에만 Applied가 되며 복구는 현재 파일에 대한 새 계획과 승인을 전제로 한다. 이 상태 모델은 구현 검증을 대체하지 않는다.

모듈별 재현 조건과 기대 결과는 [설계 검증 계획](VERIFICATION_PLAN.md)에 명시했다. 이는 후속 시험 계획이며 실행 증거가 아니다.

## 상태 전이 기계적 점검

2026-11-16에 ARC-06·07 Mermaid 상태 그래프를 추출해 시작 중 취소, 취소 결과 불명, Unknown 복구, 정상 종료 후 평가, 미확인 실행 차단, 재시도 경로, ARC-06 종료 상태의 재진입 금지 및 주요 Runtime 상태의 작업 상태 대응을 확인했다. 검사 결과 8개 조건이 모두 통과했다. 이는 문서에 해당 전이가 존재하는지 확인하는 정적 검사이며 경합의 모든 가능한 경우, 상태 전이 조건의 구현 또는 보안 강제를 증명하지 않는다. 시작 중 취소와 승인 검사 직후 경로 변경의 경합은 검증 계획에 추가했다.

ARC-00의 ADR-001~012에 대한 방향·미검증 사항·관련 문서는 [기준 결정 검토표](ADR_BASELINE_REVIEW.md)에서 추적한다.

모듈별 생산자·소비자와 버전·승인·오류 조건의 대조 결과는 [모듈 경계 계약 검토](CONTRACT_REVIEW.md)에 정리했다.

ARC-00은 대화로 전달된 원문 그대로 한 줄로 보존되어 있어 별도의 [읽기용 사본](ARC-00-READABLE.md)을 만들었다. 공백과 HTML·Markdown 이스케이프를 정규화한 문자열이 원문과 같고, 섹션 16개와 Mermaid 다이어그램 3개의 렌더링을 확인했다. 표기 복원은 원문을 대체하지 않는다.

요구사항별 근거와 사용자 승인 대기 항목은 [완료 점검](COMPLETION_AUDIT.md)에 정리했다.
