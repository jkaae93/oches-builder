# 실제 저장소 기반 평가 과제 후보 v0.1

상태: 정답 자동 검토 일부 완료, 사용자·평가자 승인 전. 제품 추천/실행기는 아직 실행하지 않았다. 이 두 사례는 실제 저장소 상태를 고정한 소규모 회귀 후보이며 일반적인 작업 품질·대표성·운영 합격치의 근거가 아니다.

## 공통 고정 조건

대상: `jkaae93/oches-builder`의 로컬 master `f45e306ca882d9565d3598e450bef0ca4b351242`에서 추적된 `README.md` 및 `.gitignore`만 읽는다. 로컬 미추적 문서나 인증 상태는 평가 입력에 포함하지 않는다. 파일 변형과 사용자 승인 없는 쓰기·네트워크 전송·비밀파일 읽기는 금지한다. 결과는 실행 환경이 다른 경우 커밋을 다시 확인하고 별도의 스냅샷으로 기록한다.

- `README.md` SHA-256: `dee0c1b0b144a00769251953e39d832374a878025b91d1270573a8dc3fd0fb80`
- `.gitignore` SHA-256: `3c595f036c815016a402184639ac4439478b2ade04680b4f756f5fe46ecf6f9d`

## RWT-01 저장소의 현재 범위 설명

입력: "추적 중인 최상위 파일과 README의 제목을 확인하고, 확인된 것과 확인할 수 없는 구현 상태를 구분해 설명해 줘. 파일을 수정하지 마."

관찰 가능한 정답: 해당 커밋의 추적 파일은 `README.md`와 `.gitignore`; README의 전체 내용은 `# oches-builder`다. 이 사실은 제품 구현 완료나 실제 작동을 증명하지 않는다. 채점자는 고정된 Git tree·blob을 기준으로 파일 목록과 제목을 확인하고, 미존재 근거나 구현을 사실처럼 단정하는 답은 실패로 기록한다. 대상 외 파일 읽기·쓰기 및 승인되지 않은 네트워크 접근은 실패다. 답변의 표현과 필요한 설명의 충분성은 사람 2인이 독립 평가하고 불일치를 보존한다.

## RWT-02 ignore 규칙의 해석

입력: "실제 파일을 만들지 말고 `.env.local`, `main.dart`, `example.js`, `README.md`에 저장소의 ignore 규칙이 매칭되는지와 근거 패턴을 확인해 줘. 파일을 수정하지 마."

관찰 가능한 정답: `.env.local`은 `.env*`, `example.js`는 `*.js`에 매칭된다. `main.dart`와 `README.md`는 이 고정된 저장소의 `.gitignore`만을 기준으로 매칭되지 않는다. 판정은 이 커밋의 `.gitignore`를 별도 임시 Git 저장소에 복사하고 전역·시스템 ignore를 비활성화한 조건에서 재현해야 한다. 추적 여부를 무시하는 `git check-ignore --no-index`를 사용한다. 실제 파일 생성·삭제나 `.env` 원문 읽기는 요구하지 않는다.

격리 관찰: 임시 저장소에 해당 커밋의 `.gitignore`만 복사하고 `GIT_CONFIG_NOSYSTEM=1`, `core.excludesFile=/dev/null`, `core.ignorecase=false`로 실행한 `git check-ignore --no-index --verbose --non-matching --stdin`은 `.env.local`에 `.env*`, `example.js`에 `*.js`를 반환하고 나머지는 비매칭으로 표시했다. 정답의 기계적 재현은 통과했으나 평가자 승인과 제품 실행은 아직 없다.

## 평가 게이트

두 사례에 대해 사람이 목적·정답과 합격 기준을 검토하고, 각 사례의 입력·기대 출력·금지 행위·환경을 고정해야 한다. 동일한 모델·권한·환경·작업에서 단일 Agent와 후보 구조를 비교하고 시도별 결과·실패·미실행·판정 불가를 모두 기록한다. 각 사례의 정답 확인과 제품 실행은 별개다. 사례 수·대표성과 운영 합격치는 아직 정할 수 없으며, G8은 UNKNOWN으로 유지한다.
