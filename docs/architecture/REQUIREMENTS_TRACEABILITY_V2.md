# 제품 목표·요구사항·수용 증거 추적 v0.2

상태: 독립 검토를 위한 제안 · 2026-11-16. 기준: ARC-00 v0.1~v0.3, ARCHITECTURE_GOALS, TEMPLATE_SYSTEM_OVERVIEW, 기존 REQUIREMENTS_ACCEPTANCE와 VERIFICATION_PLAN. 기존 R-01~12 및 V-01~16을 대체하거나 PASS 판정을 수정하지 않는다. 아래 RT 번호는 세분화된 추적 ID다. 실제 제품·모델·Provider 및 OS 권한 집행은 아직 시험하지 않았으며 별도 표시가 없는 실제 시험은 **NOT RUN**이다. 각 기대 결과는 제안이고 사용자/평가자 승인 전이다.

## 새 검증 사례: 입력·독립 증거·판정

아래는 구현 전 판정 계약 제안이다. 증거가 불완전하면 PASS가 아니라 INDETERMINATE/NOT RUN이며 관측된 위반은 다른 증거가 없어도 FAIL이다. 보안 관련 0건은 양성 대조와 명시된 부정 대조 전부에 적용한다.

|---|---|---|
| N01 | 분석 후 파일 변경, 파일 읽기 실패. 고정 fixture와 분석 시각 기록 | 새 버전 또는 stale 표시; 결과 해시·버전·UI 관측 |

## 검토 시 발견된 공백과 우선순위

1. **실제 시험 증거 부재:** 일부 시제품·모의 oracle 결과는 존재하나 제품의 독립 강제·관측기는 없다. G2·G3·G8 UNKNOWN을 유지한다.
2. **요구의 분해:** 기존 R-11의 한 행으로 Gallery·편집·버전·가져오기·추천·정본을 모두 검증했다고 주장할 수 없어 RT-25~32와 N12~18로 세분했다. 각 시험은 제안이며 미실행이다.
3. **보안 양성 대조:** 부정 사례만으로 정상 사용자의 허용과 공격 거부가 동시에 충족됐다고 판단할 수 없다. N02/06/11/18/21은 정상 주체 양성과 위조·경합 부정을 함께 요구한다.
4. **성능·접근성·지원 범위:** 정량 임계치와 OS/Provider별 지원 표시는 아직 승인되지 않았다. 측정 가능한 통과값으로 가장하지 않는다.
5. **현재 제품 경계와 요구의 차이:** Core 단일 로컬 호스트 제안과 VS Code SSH/WSL/Dev Containers 목표는 아직 통합 검증이 없다. 원격 연결 미지원/unknown을 명시하고 N19/20과는 별도로 위치별 시험을 추가해야 한다.
6. **완료 조건:** 개별 ARC 사용자의 승인과 설계 산출물 검토는 실운영 지원·릴리스 승인과 별개다. 시험 결과 없이는 제품 PASS가 아니다.
