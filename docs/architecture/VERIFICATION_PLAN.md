# Oches Build Studio 설계 검증 계획

상태: 검토용 제안 · 2026-11-16. 이 문서의 시나리오는 아직 실행한 테스트가 아니다. 대화에서 제공된 ARC-00 v0.1 및 ARC-01~10을 기준으로 한다. 실제 CLI 및 OS를 대상으로 한 실험은 버전·계정·공식 정책을 먼저 확인하고 사용자 승인 범위 내에서 진행한다.

## 설계 검토 완료 기준

모든 ARC 문서가 책임과 비책임, 기능·비기능 요구, 공개 계약 및 실패, 데이터와 상태, 정상·실패 시나리오, 보안, 테스트, 완료 조건, ADR·의존성과 미결정을 포함해야 한다. 개별 사용자 승인 전까지 설계 항목은 Done이 아니다. 문서의 미정인 임계값과 Provider 기능은 확정된 제품 지원으로 취급하지 않는다.

## 전체 수직 흐름 시나리오

1. 프로젝트 범위를 미리 보고 승인한다. 비밀파일 제외와 접근 실패가 Profile에 표시된다.
2. Profile과 최신 Capability를 사용하여 단일 기준선 및 제안·대안을 만들고 사용자가 검토한다.
3. 정의 변경 계획과 diff를 승인하고 기대 버전이 일치할 때 적용한다. 이 승인은 실행 권한과 별도다.
4. 공식 인증 상태, 계정 참조, 필수 Capability 및 실행 승인을 재확인한 후 작업 시도를 기록하고 시작한다.
5. 사용자에게 이벤트와 상태를 표시하고, 취소·실패·Unknown을 구분한다. 검증 결과가 확인되기 전 작업 성공으로 표시하지 않는다.
6. 상태·원본 근거·산출물·승인된 지식을 구별해 기록하고 접근 범위에 맞춰 필요한 컨텍스트를 선택한다.

## 장애 주입과 보안 게이트

- 시작 의도 저장 전후, 프로세스 생성 전후, 종료 관찰과 저장 사이에서 앱을 중단한다. 외부 프로세스와 로컬 트랜잭션은 원자적이지 않으므로 중복 부작용을 자동으로 허용하지 않아야 한다.
- 상태 저장 불가, 디스크 부족, 프로세스 식별자 재사용, 이벤트 유실, 시작 중 취소와 프로세스 생성 경합, 승인 검증과 파일 접근 사이의 경로 변경, 승인 철회 및 재시도 상한을 각각 주입한다. 결과는 OS·CLI·버전과 함께 기록한다.
- 비밀파일, 악성 지시가 포함된 프로젝트 텍스트, 외부 전송 승인 부재, 경로 이탈 및 동시 계정 설정 충돌을 검증한다. Worktree의 사용은 샌드박스 검증을 대체하지 않는다.
- 정량 평가에는 작업 집합·환경·반복 횟수·사용 가능한 비용/시간 측정·기준선·합격치를 먼저 명시한다. 설계 검증용 제안은 REQUIREMENTS_ACCEPTANCE를 따르며 운영 품질 기준은 미정이다.

## 증거 기록 양식

각 실행은 시나리오 ID, 실행 일시, OS와 버전, CLI·Adapter 버전, 계정 유형과 공식 지원 근거, 준비 상태, 입력과 승인 범위, 관측 결과, 기대 결과와 차이, 재현 방법, 민감정보가 제거된 증거 위치 및 판정자를 기록한다. 미실행은 통과가 아니다. 로그와 증거에는 토큰·쿠키·민감 프로젝트 원문을 넣지 않는다.

V-17의 임시 DB 실험은 삭제 원장이나 복원 제품의 합격이 아니다. 각 사례는 해당 환경·버전·양성 및 음성 대조를 확보한 뒤 독립 관측 결과로 판정한다. 후보 계약이므로 시험 추가 자체는 점수 상승 또는 Gate PASS의 증거가 아니다.

V-23의 중복 키 및 숫자 차이는 [합성 입력 실험](contracts/observe_json_parsers.py)으로 재현 가능하다. 이는 후보 규격의 reference vector가 아니며 서명 알고리즘, UI 해석, Core 메시지 처리 또는 각 플랫폼의 신원 보호를 검증하지 않는다. RFC 8785와 일치하는 직렬화·파싱 정책의 결정과 독립 구현 비교는 별도로 필요하다.
