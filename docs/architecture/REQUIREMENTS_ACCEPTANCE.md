## 추천과 평가의 고정된 초기 시험 설계
기준선은 같은 Profile, 정책, Capability snapshot과 자원 한도에서 Single Agent를 선택하는 규칙 기반 제안이다. 제안된 합성 fixture는 [recommendation-v0.1.json](fixtures/recommendation-v0.1.json) 20개이며 사람이 실제 사용 적합성과 정답을 승인하기 전이다: 단순 5, 병렬 의존성 5, 필수 미지원/unknown 5, 보안·모순 입력 5. 각 fixture의 제약·필수 및 금지 속성과 [관측 기반 oracle](fixtures/ORACLE.md)을 제안했으며 실행 전 사람이 정확성과 허용 후보를 확정한다. 추천기는 각 fixture 3회 실행하며 deterministic한 검증기는 각 회차 100% 필수 제약을 만족해야 한다. 단순 5개에서는 최소한 단일 구조가 유효한 대안으로 모두 제시되어야 한다. 실행 가능 판정에서 필수 unknown 0건, 근거 없는 지원 주장 0건이 필수다. 모델이 비결정적인 경우 세 반복의 개별 결과와 실패를 모두 보고하며 평균으로 실패를 가리지 않는다. 이 집합은 설계 검증용 기준이며 일반 품질 향상이나 실제 업무 대표성을 입증하지 않는다.

실제 작업 성공률은 정답과 통과 조건이 정해진 별도 fixture가 준비된 후 동일 작업·환경·권한·시도 수로 단일 기준선과 비교한다. 최초 20개, 각 3회 반복을 목표로 하되 미실행·실패·판정 불가를 분모와 함께 보고한다. 시간은 wall clock, 비용은 공식 제공 값만 통화·기간과 함께 기록하며 unavailable을 0으로 기록하지 않는다. 성능 우월성이나 비용 절감을 출시 기준으로 주장하려면 별도 표본 규모와 합격치를 사전에 승인해야 한다.

## 시험 증거와 게이트
각 시험은 ID, 설계·fixture·기준 버전, OS·CLI·Core·Adapter 버전, 공식 지원 근거, 준비·계정 유형, 입력, 실행 시각, 실제·기대 결과, 증거 위치, 판정자, PASS/FAIL/NOT RUN/BLOCKED 및 잔여 한계를 기록한다. 테스트 이력과 민감정보는 분리한다. Core 인증, 저장 내구성, Provider 실제 지원 중 하나라도 실패·미실행이면 해당 기능 출시 불가다. 문서 검토 통과와 실제 기능 통과를 분리한다.
