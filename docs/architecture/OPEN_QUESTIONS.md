# 미결정 사항 및 검증 계획

기준: 사용자가 대화로 제공한 ARC-00 v0.1. 원본은 대화 기록에서 ARC-00.md로 보존했으며 원격 master에는 아직 등록되지 않았다. 아래는 결정 또는 지원 보장이 아니다.

| 항목 | 확인할 내용 | 담당 설계 |
|---|---|---|
| 기준 문서 | 사용자 제공 원문은 로컬에 보존·대조 완료; 원격 등록과 버전 관리 방법 결정 | ARC-00 |
| MVP | 최초 OS와 CLI, 수직 흐름의 수용 기준 | 전체 |
| 인증 | Provider 공식 로그인과 외부 GUI 연동 허용 범위 및 약관 | ARC-05 |
| 격리 | 동시 계정·세션별 독립 환경 지원 및 전역 설정 영향 | ARC-05/06 |
| Runtime | 이벤트·취소·재개·복구의 공식 지원 및 버전 차이 | ARC-06 |
| 안전 | OS별 샌드박스, 승인 강제 가능 범위, 작업 디렉터리와의 차이 | ARC-06/09 |
| 데이터 | 로컬 코어 언어·IPC, SQLite 스키마, 이벤트 보존·민감정보 제거 | ARC-10 |
| 평가 | 기준선·데이터셋·비용과 사용량의 실제 가용성 | ARC-03/09 |
| 외부 전송 | Provider에 전송되는 정보, 정책 및 사용자 표시 | ARC-02/05/06 |
| Antigravity | 공식 자동화·인증·GUI 연동 계약 및 지원 범위 | ARC-05 |
| Orca | 특정 버전 소스와 라이선스 확인 | ARC-05 |
| Projects | In Review 상태 추가 또는 기존 상태 매핑 | 관리 |

Claude Code와 Codex의 공식 로그인 문서는 존재하지만, 이것만으로 외부 GUI의 인증 위임, 계정 격리, 구독 사용 허용 또는 세션 재개를 증명하지 않는다. 공식 문서의 버전·조건·접근일과 실제 환경 실험을 함께 기록해야 한다.

## 멀티 클라이언트 추가 미결정
- Core 프로세스 및 배포 방식, Desktop 없는 설치·종료·업데이트, 클라이언트별 인증 발급·회수·버전 협상.
- Native Messaging Host 등록·위변조 방지와 Core 인증, localhost 보조 경로의 위협 모델과 사용 여부.
- VS Code SSH·WSL·Dev Containers에서 Core 위치, workspace URI·Trust 및 데이터 이동 범위.
- Chrome의 최소 버전, Side Panel·Worker 재연결, 권한 요청 범위 및 Chrome Web Store 최신 정책.
- 클라이언트별 Capability·승인 정책, 원격과 로컬 workspace의 식별, 동시 변경 충돌과 이벤트 복구.

## 템플릿 시스템 미결정
- 기본 제공 후보와 각 Provider Capability 요구, 교환 형식의 실제 스키마 및 YAML 파서 제한.
- 스키마 버전·마이그레이션, 사용자 템플릿 삭제 및 과거 버전 참조 정책의 상세 UX.
- 조건 분기·유한 반복과 재사용 서브그래프의 표현 및 안전성 검증.
- 사용자 데이터·계정 참조·경로의 내보내기 범위와 비밀정보 검출 한계.
- Desktop·VS Code·Chrome의 편집 기능 범위, 원격 Core 위치와 정본 동시성.

## 후속 설계 상태 · 2026-11-16

위 내용은 작성 당시의 기록이다. 이후 [ARC-11](ARC-11.md)~[ARC-14](ARC-14.md) 설계 제안과 [요구사항·수용 기준](REQUIREMENTS_ACCEPTANCE.md), ARC-09/10 보완 계약을 추가했다. 사용자 승인과 실제 OS·Provider·저장소 시험은 미완료이며 GitHub Projects 상태를 자동 변경하지 않았다. 과거의 미착수·미정 표현은 이 후속 설계의 존재나 제안된 기본값을 부정하지 않는다.
