# Oches Build Studio 아키텍처 목표

상태: 계획 초안 · 2026-11-15. 기준: 사용자가 대화로 제공한 Local Agent Studio ARC-00 v0.1. 원본은 대화 기록에서 복원하여 ARC-00.md에 보존했다. 원격 master에는 아직 등록되지 않았다.

[ARC-00](ARC-00.md)은 대화로 제공된 v0.1 원문을 앞부분에 보존하고 v0.2 부록을 추가한 파일이다. [ARC-00 읽기용 사본](ARC-00-READABLE.md)의 v0.1 부분은 HTML·Markdown 이스케이프와 줄바꿈을 정리한 것으로, 정규화 후 원문과 문자 내용이 일치하는지 확인했다. 원문의 Local Agent Studio는 이전 가칭이며 현재 제품명은 Oches Build Studio다.

## 제품 목표
사용자가 목표와 로컬 프로젝트 환경을 입력하면 GUI에서 적합한 에이전트 구조를 추천받고 근거와 대안을 검토·수정하여, 공식 인증을 이용하는 로컬 실행 환경에서 실행·관측·평가·관리하는 Local-first 데스크톱 플랫폼. Local Agent Studio는 이전 가칭이다.

## 설계 성공 기준
- 하나의 OS와 공식 연동이 가능한 CLI 하나를 선정해 프로젝트 선택부터 승인, 실행, 취소, 결과 및 이력 확인까지 수직 흐름을 검증한다. 대상은 미정이다.
- 단일 에이전트를 기준선으로 삼고 복잡한 구조는 근거와 대안 및 비용·지연·정확성 가정을 명시한다.
- Runtime, 모델, 계정, 세션을 구분하고 Provider의 미지원·미확인 기능을 사용자에게 표시한다.
- 프로젝트 데이터와 실행 상태의 로컬 보관과 Provider로 전송되는 정보를 구분한다. 비밀정보는 일반 데이터베이스와 로그에서 제외한다.
- 승인 경계, 실패·중단·미완료 구분, 원본 근거와 검증된 지식 분리를 설명하고 검증한다.
- 사용자 목표에 대한 성공률·시간·비용은 공식 데이터의 가용 범위와 측정 조건을 명시해 기준선과 비교한다.

## 기존 방향과 검토 결과
ARC-00의 다섯 논리 계층과 ADR-001~012는 유지한다. Flutter, 중립 스키마, 공식 인증, 상태와 기억 분리는 설계 방향이지 검증된 구현이 아니다. 코어 언어·IPC, SQLite 스키마, OS/CLI, 격리와 복구 지원은 미정이다. 세션별 계정 격리와 승인 강제는 Provider의 공식 인터페이스로 가능한지 검증 전까지 보장하지 않는다. Git Worktree는 보안 샌드박스가 아니다.

## 근거와 적용 구분
[Anthropic의 에이전트 패턴](https://www.anthropic.com/engineering/building-effective-agents)은 단순한 구성에서 출발하고 필요에 따라 복잡성을 늘리는 접근을 설명한다. 본 제품의 단일 에이전트 기준선은 이에 근거한 설계 제안이다. [에이전트 평가 자료](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)는 평가 및 회귀 측정을 논의한다. 본 제품의 지표·데이터셋은 아직 확정되지 않았다. 발행일은 각각 2024-12-19, 2026-01-09로 Anthropic 공개 목록에서 확인했다. 지원 범위는 구현 전 재확인한다.

## 2026-11-16 멀티 플랫폼 확장
제품 목표는 Desktop, VS Code Extension, Chrome Extension을 통한 일관된 Local-first 경험으로 확장한다. 이 플랫폼들은 공식 대상이나 실제 OS·버전별 지원은 미검증이다. Desktop은 전체 기능을 목표로 하며 Extension은 제한된 Capability와 권한을 적용한다. 공유 Core의 배포와 Desktop 없이 연결하는 경로는 [ADR-014](adr/ADR-014-multi-client.md)의 가설을 검증한다. 원본 ARC-00 v0.1은 보존하고 v0.2 부록을 추가했다.

## 템플릿 시스템 확장
추천된 구성을 선택·수정할 뿐 아니라 빈 구성에서 시작하고 사용자 템플릿으로 로컬 저장·재사용하는 흐름을 제품 목표에 추가한다. 기본 템플릿 후보의 범위와 실제 Runtime 지원은 검증 후 확정한다. 템플릿과 프로젝트 인스턴스는 독립적으로 관리한다.
