# Design

Use the Core raw JSON parser before typed validation so duplicate keys, unsafe numbers and unknown fields cannot disappear during decoding. Apply ARC-04 and DESIGN_FINALIZATION S1–S3 limits. Preserve UTF-8 identity in identifier uniqueness checks. Export mappings require versioned evidence; validation alone grants neither export support nor permission to write. Implement schema validation first, then export planning and authorized application with transaction and filesystem failure evidence.

Persist published definition versions as separate create-only ARC-04 objects keyed by definition ID and declared version. SQLite assigns a distinct storage RevisionRef; declared definition version and storage revision are separate concepts. Preserve old published objects when publishing new versions. Existing transactional state/event/idempotency tables suffice, so this step adds no schema migration. The internal repository is not an authenticated product endpoint; authorization and deletion integration remain required before exposing publication or retrieval.

Represent the reviewed diff as exact previous/proposed UTF-8 bytes, with absent targets distinct from empty files. A separate export-document digest binds the mapping-plan digest and both content hashes. Approval requests use this document digest, not the mapping-only digest. Limit each content snapshot to 256 KiB and reject invalid UTF-8 and NUL bytes. Creating an approval request binding does not issue or consume approval. Authenticated approval verification and descriptor-safe filesystem application remain separate pending work.

Config-apply authorization inputs must include the exact expected approval binding derived from the reviewed document. Compare its canonical byte identity inside the approval-consumption transaction, require the request digest to match the approved document digest and bind the canonical target. Include this expected binding in idempotency identity so a cached result cannot be retrieved using changed apply-plan fields. The internal input is not a replacement for authenticated transport or the document's current-state revalidation.

The initial internal writer uses no-follow descriptor-relative access, exclusive creation and exact existing-content checks. It writes through the held regular file descriptor, truncates after writing and verifies flushed contents. Failures after mutations are Partial or Unknown. This is not atomic replacement or authorization. Keep it disconnected until root descriptor identity, mutation races, durable intent/outcome coordination and recovery are verified; advisory locks alone cannot establish protection from uncooperative writers.

Persist apply intent/outcomes under the reviewed document digest using ARC-04 state/event/idempotency transactions. An unfinished Applying intent becomes Unknown on recovery, with no automatic writer invocation. Terminal states cannot be replaced with a late success from a stale intent reference. The journal is internal and not an approval boundary; integrate approval consumption and durable intent atomically before exposing application.

Internal apply coordination revalidates the plan, records authorized intent and invokes the writer only for a new intent. A replay queries outcome and never writes again; Applying is surfaced as Unknown without forcing a live operation into recovery. Outcome persistence failure returns Unknown. Writer callbacks are internal composition only. Optional-loss plans stay blocked until their separate consent path is integrated. This coordinator does not establish authenticated transport or eliminate filesystem races.

Hold the write-root directory descriptor after checking its current device/inode identity. Writes duplicate that descriptor instead of reopening the approved pathname. This prevents replacement roots redirecting subsequent opens, but does not prove pathname freshness or identity across restart. The approved identity must still be bound to the review/approval context, and rename policy must be enforced before product exposure.

Include the held root device/inode in the reviewed document digest. Internal apply requires this identity, and the document writer compares it with its held root before deriving a relative target and writing the document's exact approved bytes. Root identities captured across process restarts cannot be reused as authority; product session binding and rename policy are still required.

Bind each reviewed document to the held root's ephemeral UUID session as well as its descriptor identity. A newly opened root requires a new reviewed document even if device/inode match. The document writer checks the recorded canonical root path still names that directory before writing. These checks do not eliminate mutations after checking; retain the product exposure gate until the remaining race contract is enforced.
