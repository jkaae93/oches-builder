# Design

Keep graph parsing, structural semantics, reference authorization and execution permission separate. Validate task dependency DAGs with bounded iterative traversal; data edges must not implicitly introduce dependencies. A structural result grants no execution authority. Subsequent work adds the frozen six node kinds/seven relations, port typing, version-bound reports, immutable registry persistence, independent instances and reviewed migration/import.

Validate data ports independently: each source references an output and each target an input of the same non-control type; required data inputs require exactly one graph or declared external source. JSON equality alone remains compatibility Unknown. External declarations do not prove value validity or authority. Relation validation must still enforce control ownership and invoke task dependency checks separately.

Represent all six frozen node kinds and seven relation kinds in the internal structural layer. Reference relations check allowed node direction and do not carry data ports. Dependency edges connect Task control outputs to Task control inputs. Route data edges through port checks and explicit Task-order checks. Ambiguous multiple role assignments are rejected. Node-specific payload versions, proposed-action approval ownership and authorization require separate validation before this structure can form an executable template.

Bind reports to instance and definition generation/revisions, graph digest, schema, capability snapshot/version, policy and validator version. Canonicalize exact byte identities and reject duplicate definition IDs. Preserve structural/capability/policy results independently. Reject changed bindings, backward observation time and age at or beyond 24 hours. A fresh report is not execution approval, and report construction from trusted domain records remains an integration requirement.

Stage JSON exchange input only as an unvalidated candidate after bounded raw parsing and strict envelope/metadata/version checks. Preserve raw node/edge payloads and canonical content identity. Candidate parsing is not full node validation, publication, authorization or execution; full schema validation and typed semantic checks must precede those operations. No YAML parser or remote schema fetching is introduced by this stage.

Persist internal import candidates as create-only ARC-15 state objects using existing SQLite atomic state/event/idempotency transactions. Retain untrusted provenance separately and include it in request identity. Exact generation/revision and a 24-hour lifetime gate candidate reads; expiry must not renew on replay. Staging never executes or publishes a graph. Product ID allocation, authorization, physical expiry cleanup and reviewed import confirmation remain separate integration requirements.

After TTL expiry, an internal revision-checked transition redacts current candidate content/provenance while retaining an expired marker and request identity. Replays cannot repopulate the expired candidate. This is logical state redaction, not disk/WAL/backup erasure; cleanup scheduling and deletion/recovery enforcement remain pending.

Store immutable family/version content snapshots separately from mutable instance objects. Creating an instance copies the source bytes and exact source revision; edits affect only that instance using expected revision checks. These primitives do not confer Published status or validate full node semantics. Family revision checks, built-in restrictions, full validation and reviewed publication/import must be integrated above this storage adapter before exposing it.

Task exchange payloads use strict keys `id`, `kind`, `label`, `goal`, `inputs`, `outputs`, `resourceLimits`, `requirements`, with optional `externalInputs`. `resourceLimits` contains integer-token `maxDurationSeconds` (1–86400) and `maxRetries` (0–3), following frozen R2/R3. Agent payloads retain the documented embedded definition shape. These declarations do not prove runtime enforcement; Task role/evaluation requirements and domain payload reference resolution must still be validated before publication/execution.

Non-Agent nodes share `id`, `kind`, `label`, `inputs`, `outputs`, `requirements` and optional `externalInputs`. Tool adds `capability` and `permissions` (action/scope/approvalRequired). Memory adds `memoryRef` and nonempty `evidenceRefs` (at most 256). Evaluation adds `criteriaRef` and `evaluatorRef`. Approval adds `action`, `targetRef`, `scope` and integer-token `expiresAfterSeconds` (1–900). Domain references use `{id, revision}` with ASCII logical IDs and canonical positive decimal revision strings. These implementation wire choices express declarations, not actual accounts, executable paths, resolved permissions, runtime artifact manifests or user decisions. Resolve references and apply the owning domain's authorization separately before publication/execution.

Root requirements use the same strict capability and permission record shapes as node declarations. Retain every domain reference's node, role, logical ID and revision and the full exchange digest alongside the structural projection. This projection is not authority; domain owners must resolve existence, current revision and access under authenticated workspace context before Registry publication or execution.

Report bindings distinguish full exchange identity from the structural graph projection. Candidate-report creation reparses canonical content, requires the full exchange digest, validates decoded declarations and compares the structural digest. Changing instructions, permission declarations or other payloads invalidates the report even when topology and ports remain unchanged. Structural-only helper reports are not sufficient for candidate publication or execution.
