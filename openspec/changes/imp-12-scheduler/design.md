# Design

Follow ARC-07 and frozen R3–R5/R10/R11. Validate the DAG before planning, require verified Task success for predecessors, preserve FIFO among eligible tasks and allow at most four reserved/active/uncertain attempts per workspace. Unverified installation/account isolation serializes that combination; conflicting canonical resource identities serialize separately. Planning never spawns a process or grants approval. Cross-Run workspace inspection lets subsequent Runs claim remaining capacity up to four slots without exceeding workspace isolation or exclusive-resource bounds.

Store the Run's initial plan/input digest (and optional instanceRevision) create-only and update only task/reservation/attempt-binding/retry/evaluation state through expected-revision transitions. Reservation IDs and request results commit together; replay returns recorded IDs without replanning side effects. Cross-Run slot/account/resource conflicts are enforced atomically inside `BEGIN IMMEDIATE` via `SQLiteStore.commitSchedulerReservation`. Prepared Runtime attempts namespace `taskID` as `arc07/run/<runID>/task/<taskID>` and bind `taskRevision`, `instanceRevision`, `bindingDigest`, `executionRequestDigest` and `capabilitySnapshotID`; `RuntimePrepareAndStartGate` checks all execution approval binding fields and transfer `accountRef` before pre-spawn transition.

Retry policy distinguishes confirmed Runtime failure, verified evaluation failure and manual Interrupted recovery, persisting `retryCounts`, `lastFailureTimestamps`, `attemptHistory` and clearing old reservation/binding state only when eligible so every retry allocates a fresh `attemptID`, increments `taskRevision`, and requires fresh execution approval. Keep Unknown and active/cancelled attempts ineligible. Enforce at most three reserved retries with exponential delay (1s/2s/4s within bound, 60s cap).

`observeRuntime`, `cancelTask` and `reconcileAfterRestart` verify full attempt identity/binding and apply ARC-06 mapping (`CancelRequested` stays `Running`, `Succeeded` becomes `Evaluating`, `Unknown`/`Interrupted` become `Blocked`). `EvaluationVerdictStore` + `SQLiteStore.commitSchedulerEvaluation` atomically verify an active, non-stale `evaluation_records` row (`PASS`/`FAIL`/`INDETERMINATE`) and `execution_attempts.state == 'Succeeded'` inside `BEGIN IMMEDIATE` before advancing Task state (and unlocking dependent tasks on `PASS`). IMP-13 immutable artifact collection/independent observation, authenticated XPC product endpoints, and real Claude/Codex Provider adapters remain out of scope for this Core scheduler boundary.
